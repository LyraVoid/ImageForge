# Contributing

Thanks for looking. This project has a few firm rules, because almost everything it does is a
byte-level contract with software that runs on someone else's phone.

## Getting set up

    pnpm install
    pnpm dev                 # development server on http://127.0.0.1:5173/
    pnpm verify              # docs check, typecheck, lint, tests, build — the gate

`pnpm verify` is what has to pass before a change is merged; CI runs the same four stages
(`.github/workflows/ci.yml`). Node 20+ and pnpm 9+ are enough: the compiled WebAssembly modules are
committed, so no Rust or C toolchain is needed unless you are rebuilding one of them.

## The rules

The short list is in [AGENTS.md](AGENTS.md) and the full one under **Hard rules** in
[docs/architecture.md](docs/architecture.md). The parts that surprise people most:

* **Never verify a byte-level format against something this project produced.** Use the reference
  implementation, read it and cite `file:line`, or compile it to WebAssembly and use it directly, or
  treat a mature tool as an oracle and compare byte for byte. `docs/architecture.md` explains the
  order, with the bugs each approach found.
* **A test that needs material skips itself** and names the environment variable that supplies it.
  `docs/testing.md` lists the variables, where each one looks and how the material was captured;
  that table is generated by `scripts/materials.mjs` and CI fails when it drifts.
* **Bundled artifacts are digest verified before use**, registered with a pinned revision in
  `THIRD_PARTY_LICENSES/`, and a payload has to be what it claims to be — a module is a relocatable
  ELF whose `vermagic` matches its KMI, a core image starts with `KP1158`, a stub is an APK. A digest
  alone only proves a file did not change.
* **ImageForge never flashes a device.** The pipeline ends at a downloaded image.

## Adding a manager or a bundled artifact

The steps are the same every time, and the register is what makes them checkable:

1. Read the upstream source at the revision you intend to pin, and find out exactly what its patcher
   writes: which files, which modes, which configuration keys, which codes settings.
2. Put the payloads under `public/artifacts/<manager>/` and add a release to
   `src/core/artifacts/catalog.ts` with the size and SHA-256 of every one.
3. Write `THIRD_PARTY_LICENSES/<manager>/README.md`: upstream URL, pinned revision or tag commit,
   license, the table of payloads with their digests, how to reproduce them from the release, what
   the patcher does differently from the upstream it forked, and — explicitly — what you could **not**
   verify. Copy the upstream `LICENSE` next to it.
4. If it is a flavour of an existing provider, add it to that provider's flavour table and to
   `src/core/patch/manager-apps.ts`; if it is a new method, add a provider and a descriptor.
5. Translate the new user-visible sentences into `src/i18n/record/{zh-Hans,zh-Hant,ja}.ts`; the
   coverage test names the ones you miss.
6. Add tests: the digests, the flavour mapping, and at least one run against real material.

If the payloads exist only inside an APK, `scripts/scan-embedded-elf.py` recovers them and
`THIRD_PARTY_LICENSES/kernelsu/README.md` shows the whole procedure, including which `vermagic` means
which KMI.

## Commits and pull requests

* Commit messages are English, imperative and explain **why**; the diff already says what.
* Keep unrelated changes apart, and say in the message what you ran.
* A new bundle rebuilds the modules it changes: `pnpm wasm:build`, `pnpm wasm:build:kptools`,
  `pnpm wasm:build:lz4`, `pnpm wasm:build:bzip2`. When a module's bytes change, its digest has to be
  updated in `src/wasm/assets.ts` or in the catalog — the tests fail until it is.

## Reporting bugs

Include the **diagnostics export** from the result page: it carries the plan, the metadata and the
artifact names as JSON, with no image bytes and no secret in it. For a crash, the browser console is
what we need most. Security issues go through [SECURITY.md](SECURITY.md) instead of the issue
tracker.
